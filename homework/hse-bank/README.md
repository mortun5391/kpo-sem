# HSE Bank - Financial Accounting System

Консольное приложение для учета личных финансов.

## Функциональность

### Основная функциональность
- ✅ Создание, редактирование, удаление банковских счетов
- ✅ Создание, редактирование, удаление категорий операций
- ✅ Создание финансовых операций (доходы/расходы)
- ✅ Валидация данных при создании объектов

### Дополнительная функциональность
- ✅ Расширенная аналитика финансовых данных
- ✅ Импорт данных из CSV, JSON, YAML
- ✅ Экспорт данных в CSV, JSON, YAML
- ✅ Пересчет балансов счетов
- ✅ Измерение времени выполнения операций

## Архитектура и паттерны

### Реализованные паттерны GoF

#### 1. Фасад (Facade)
- **Классы**: `BankAccountFacade`, `CategoryFacade`, `OperationFacade`, `AnalyticsFacade`
- **Назначение**: Упрощение работы с сложными подсистемами, предоставление единого интерфейса

#### 2. Команда (Command)
- **Классы**: Интерфейс `Command` и реализации (`CreateAccountCommand`, `CreateCategoryCommand`, etc.)
- **Назначение**: Инкапсуляция пользовательских сценариев в объекты

#### 3. Декоратор (Decorator)
- **Классы**: `TimedCommandDecorator`
- **Назначение**: Динамическое добавление функциональности (измерение времени) к командам

#### 4. Шаблонный метод (Template Method)
- **Классы**: `DataImporter` и наследники (`CsvDataImporter`, `JsonDataImporter`, `YamlDataImporter`)
- **Назначение**: Определение алгоритма импорта с возможностью переопределения шагов

#### 5. Посетитель (Visitor)
- **Классы**: `DataExportVisitor` и реализации (`CsvExportVisitor`, `JsonExportVisitor`, `YamlExportVisitor`)
- **Назначение**: Операции над различными типами объектов без изменения их классов

#### 6. Фабрика (Factory)
- **Классы**: `DomainFactory` интерфейс и `DomainFactoryImpl`
- **Назначение**: Централизованное создание доменных объектов с валидацией

#### 7. Прокси (Proxy)
- **Классы**: `BankRepositoryProxy`
- **Назначение**: Кэширование данных и контроль доступа к реальному репозиторию

#### 8. Стратегия (Strategy)
- **Назначение**: Динамический выбор импортеров/экспортеров based on file format

### Принципы SOLID

#### Single Responsibility Principle
- Каждый класс имеет одну четкую ответственность
- Пример: `BankAccount` отвечает только за логику счета, `Operation` - за операции

#### Open/Closed Principle
- Легко расширяемы системы импорта/экспорта
- Новые команды добавляются без изменения существующего кода

#### Liskov Substitution Principle
- Все наследники `DataImporter` и `DataExportVisitor` могут заменять родительские классы

#### Interface Segregation Principle
- Узкоспециализированные интерфейсы: `Command`, `InputProvider`, `DataExportVisitor`

#### Dependency Inversion Principle
- Зависимости определяются через интерфейсы
- Внедрение зависимостей через Spring DI

### Принципы GRASP

#### High Cohesion
- Логически связанные методы сгруппированы в соответствующих фасадах
- `AnalyticsFacade` содержит всю аналитическую логику

#### Low Coupling
- Минимальные зависимости между модулями
- Коммуникация через интерфейсы и фасады


## Инструкция по запуску

### Требования
- Java 21 или выше
- Gradle 8.0 или выше

### Сборка и запуск

```bash
# Клонирование репозитория
git clone <repository-url>
cd hse-bank

# Сборка проекта
./gradlew build

# Запуск приложения
./gradlew bootRun

# Или запуск собранного JAR
java -jar build/libs/hsebank-1.0-SNAPSHOT.jar
```

### Тестирование

```bash
# Запуск всех тестов
./gradlew test

# Запуск с генерацией отчета
./gradlew test jacocoTestReport
```
