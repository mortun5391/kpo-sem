# Архитектура системы антиплагиата

## Обзор
Система антиплагиата представляет собой микросервисную архитектуру, состоящую из трех основных сервисов:

1. **API Gateway** - единая точка входа для клиентов
2. **File Storing Service** - сервис хранения файлов и метаданных работ
3. **Analysis Service** - сервис анализа работ на плагиат

## Компоненты системы

### 1. API Gateway
**Назначение**:
- Маршрутизация запросов к соответствующим сервисам
- Агрегация ответов от нескольких сервисов
- Обработка ошибок и fallback-механизмы
- Circuit breaker для устойчивости системы

**Технологии**:
- Spring Cloud Gateway
- WebFlux для реактивного программирования
- Resilience4j для устойчивости

### 2. File Storing Service
**Назначение**:
- Хранение файлов работ студентов
- Управление метаданными работ
- Валидация файлов (размер, тип)
- Предоставление доступа к файлам

**Основные функции**:
- Загрузка файлов (PDF, DOCX, TXT)
- Хранение метаданных в PostgreSQL
- Кэширование с помощью Redis
- Валидация входных данных

### 3. Analysis Service
**Назначение**:
- Анализ текста на наличие плагиата
- Генерация отчетов о проверке
- Формирование облаков слов
- Обработка событий анализа

**Основные функции**:
- Алгоритм сравнения шинглов
- Определение процента схожести
- Генерация отчетов в JSON формате
- Интеграция с QuickChart для облаков слов

## Взаимодействие сервисов

### Сценарий 1: Загрузка работы


1. Клиент отправляет файл через API Gateway
2. Gateway перенаправляет запрос в File Storing Service
3. Сервис сохраняет файл и метаданные
4. Возвращается идентификатор работы

### Сценарий 2: Анализ работы


1. Клиент запрашивает анализ работы
2. Analysis Service получает файл из File Storing Service
3. Выполняется анализ на плагиат
4. Результат сохраняется в базе данных
5. Отправляется событие о завершении анализа

### Сценарий 3: Получение отчетов

1. Клиент запрашивает отчеты по работе
2. Gateway перенаправляет запрос в Analysis Service
3. Сервис извлекает отчеты из базы данных
4. Возвращается список отчетов в JSON формате

## Базы данных

### File Storing Service Database
```sql
Table: works
- id (PK)
- student_id
- assignment_id
- original_file_name
- stored_file_name
- file_size
- mime_type
- file_path
- upload_date
- status
- created_at
- updated_at
Analysis Service Database
Table: reports
- id (PK)
- work_id (FK to works.id)
- status
- similarity_score
- is_plagiarized
- analysis_details (JSONB)
- error_message
- started_at
- completed_at
- created_at
- updated_at
```
